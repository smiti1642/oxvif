# oxvif 0.16.0 / oxvif-cli 0.1.0

Status: Unreleased

This release adds the library discovery primitives and workspace packaging for
the first `oxvif` command-line release. The CLI is designed as one typed
application surface for terminal users, Agents, CI, and fleet automation.

## Library

- `probe_result` returns discovery transport errors to callers.
- `probe_result_on` scopes WS-Discovery to explicit local IPv4 addresses.
- `discovery_interfaces` returns the non-loopback multicast interfaces that can
  be selected by a caller.
- Existing `probe` behavior remains source-compatible.

## CLI 0.1.0

- After publication, install with `cargo install oxvif-cli`; invoke it as
  `oxvif`. Until then, install from the workspace source path.
- Onboard interactively with secure `setup`/`auth`, then use concise `info`,
  `test`, `health`, `profiles`, `stream`, and `snapshot` commands against a
  positional or current device.
- Persist immutable device IDs and secret-free metadata while passwords remain
  in Windows Credential Manager, macOS Keychain, or Linux Secret Service.
  Static Groups use local aliases and dynamic Views use typed filters. The
  native lifecycle contract passes on Windows x64, macOS Intel/Apple Silicon,
  and Ubuntu x86_64/aarch64 CI; no plaintext fallback is available. Public
  release remains unpublished pending explicit approval and public-channel
  verification.
- Save, refresh, enrich, filter, and remove versioned discovery snapshots.
- Import through a deterministic SHA-256 plan/apply flow, including versioned
  secret-free ID/alias override documents.
- Read device information, capabilities, services, Media1 profiles and URIs,
  PTZ status/presets, and comprehensive health results without device writes.
- Run diagnostics across a Group or View with 16 jobs by default (64 maximum),
  deterministic JSON/JSONL, exit 6 for partial success, and `FLEET_FAILED` when
  every selected device fails.
- Use bare ephemeral discovery, registration-aware terminal tables,
  `--json`/`--jsonl` shorthands, deterministic ID suggestions, interactive
  profile selection, and generated Bash/Zsh/Fish/PowerShell completion.
- Read profiles, capabilities, services, PTZ, health, and media URIs through
  purpose-built terminal renderers instead of generic JSON dumps.
- Apply a per-attempt timeout and bounded retry policy only to transient
  transport failures; health and failed discovery interfaces honor the same
  global retry count, while authentication and deterministic protocol errors
  are not retried.
- Use `-v`/`-vv` for sanitized stderr-only command, retry-policy, outcome, and
  timing diagnostics without corrupting JSON/JSONL stdout.
- Inspect or validate registry recovery state with `config path` and
  `config validate`; orphaned snapshot files are warning-only and never removed
  automatically.
- Agents can inspect the embedded guide and 61 machine-readable command
  descriptors with named result kinds, scoped errors, semantic arguments, and
  safe examples; structured output uses schema version 3.
- Linux, Windows, and macOS CI cover tests and binary smoke; the manual release
  workflow prepares native Linux amd64/arm64, macOS Intel/Apple Silicon, and
  Windows x64 artifacts. It stages SHA-256 checksums, SPDX SBOMs, build
  provenance, normalized reproducible archives, Debian packages with
  `lintian` plus signed-repository install/remove smoke tests, and a hash-pinned
  project-tap formula with Intel/Apple Silicon bottle tests. The Windows
  portable artifact uses a static C runtime and release CI rejects unexpected
  VC runtime DLL imports. The workflow defaults to no public release until
  publication is explicitly enabled and approved.
- Release CI uses Rust 1.88.0 and immutable commit pins for every GitHub Action;
  Dependabot remains responsible for proposing reviewed action updates.

## Security and release order

Passwords are never accepted as command arguments or stored in the registry.
URI userinfo is removed from diagnostic results. Device-mutating ONVIF commands
and MCP are intentionally outside 0.1.

The beta uses platform TLS trust roots and accepts repeatable
`--ca-certificate <FILE>` PEM certificates/bundles for private HTTPS trust
anchors. The same trust configuration applies to diagnostics, health,
setup/refresh, discovery enrichment, and fleet work. Invalid/empty bundles and
private-key material fail before connection. There is no insecure-certificate
or hostname-verification bypass.

The release lockfile selects `h2 0.4.16` (addressing
`RUSTSEC-2026-0258`) and `chacha20 0.10.2` instead of the yanked 0.10.1
release. Release CI blocks on `cargo audit`.

Publish `oxvif 0.16.0` before `oxvif-cli 0.1.0`; the latter depends on the
former's discovery APIs during packaged verification.
