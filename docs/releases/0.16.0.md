# oxvif 0.16.0 / oxvif-cli 0.1.0

Released: 2026-08-27

This release adds the library discovery primitives and workspace packaging for
the first `oxvif` command-line release. The CLI is designed as one typed
application surface for terminal users, Agents, CI, and fleet automation.

## Library

- `probe_result` returns discovery transport errors to callers.
- `probe_result_on` scopes WS-Discovery to explicit local IPv4 addresses.
- `discovery_interfaces` returns the non-loopback multicast interfaces that can
  be selected by a caller.
- Existing `probe` behavior remains source-compatible.

## CLI 0.1.0

- Install with `cargo install oxvif-cli`; invoke it as `oxvif`.
- Persist immutable device IDs, secret-free metadata, native credentials,
  static Groups with local aliases, and dynamic Views with typed filters.
- Save, refresh, enrich, filter, and remove versioned discovery snapshots.
- Import through a deterministic SHA-256 plan/apply flow, including versioned
  secret-free ID/alias override documents.
- Read device information, capabilities, services, Media1 profiles and URIs,
  PTZ status/presets, and comprehensive health results without device writes.
- Run diagnostics across a Group or View with 16 jobs by default (64 maximum),
  deterministic JSON/JSONL, exit 6 for partial success, and `FLEET_FAILED` when
  every selected device fails.
- Agents can inspect the embedded guide and 47 machine-readable command
  descriptors; structured output uses schema version 3.

## Security and release order

Passwords are never accepted as command arguments or stored in the registry.
URI userinfo is removed from diagnostic results. Device-mutating ONVIF commands
and MCP are intentionally outside 0.1.

Publish `oxvif 0.16.0` before `oxvif-cli 0.1.0`; the latter depends on the
former's discovery APIs during packaged verification.
