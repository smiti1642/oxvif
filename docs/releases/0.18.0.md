## CLI and automation

- **Choose the media service.** Use `--media-service media1`, `media2` or
  `auto` for profiles, URIs, diagnosis, inventory and health media reads.
  `auto` tries advertised Media2 first and falls back when its endpoint is
  missing or the device explicitly reports an unsupported operation.
  Without the flag, `media profiles` uses Media1 and `data.result` is an
  array. With an explicit selector, `data.result` is an object with
  `profiles`, `media_service`, `endpoint_source` and `attempts`. Both forms
  use JSON/JSONL envelope schema v3.
- **Match the camera's SOAP authentication.** `--soap-auth` accepts
  `combined` (the default), `digest` or `ws-security`. Automatic clock
  synchronization uses device time for WS-Security UsernameToken.
- **Probe a stream on demand.** Run
  `oxvif --rtsp-probe describe diagnose CAMERA` to inspect SDP and the
  advertised video codec. `packet` also runs SETUP and PLAY, waits for one
  interleaved video RTP packet, and attempts TEARDOWN. Both modes leave
  `playback_verified` false. The stream must use the device host. HTTPS
  device URLs require RTSPS and certificate verification.
- **Read complete health output.** `oxvif health check --details` shows
  every check and timing in the terminal. `-vv` sends bounded session and
  retry diagnostics to stderr. JSON and JSONL reports include all checks.

See the [CLI guide](../oxvif-cli.md).

## Rust upgrade notes

These migration notes apply when upgrading from 0.17.1.

- **Handle incomplete recording searches.** `search_recordings()` returns
  `OnvifError::RecordingSearchIncomplete` when a limit, cancellation or an
  unknown state ends the search before Completed. RPC failures propagate
  as their original errors. Use `search_recordings_with_report()` to retain
  partial records, the failure reason and the independent
  `EndSearch` outcome. Call `close()` on an owned search for remote cleanup.
- **Update exhaustive matches.** Account for
  `OnvifError::RecordingSearchIncomplete`, `TransportError::Deadline`,
  `TransportError::ResponseTooLarge`, `SoapError::ResourceLimit`, and
  `HttpTransportBuildError::{InvalidTimeout, InvalidResponseLimit}`.
  Complete struct literals for the CLI library's `ExecutionOptions` need
  `soap_auth`, `media_service` and `rtsp_probe`. Use
  `..Default::default()` for fields that can take their defaults.
- **Check production SOAP fixtures and custom transports.** The response
  validator requires complete XML and enforces limits of 4 MiB, depth 64
  and 65,536 elements, including responses from custom transports. The
  built-in HTTP transport defaults to ten seconds per HTTP request and a
  4 MiB response limit. Scoped operations can apply a deadline to the
  entire SOAP exchange, including a Digest challenge and retry.
- **Use explicit captures for wire investigation.** Client trace logs now
  record operation, timing, byte count and error class. Capture wire
  messages explicitly and review device data before sharing a capture.

See the [Rust library guide](../../LIBRARY_GUIDE.md).

## New Rust workflows

- Managed pull-point subscriptions preserve qualified topics and endpoint
  parameters, renew while polling, report gaps after recovery, and support
  asynchronous close.
- Typed PTZ movement supports separate pan/tilt and zoom axes, coordinate
  spaces, speed, continuous timeout, and axis-specific Stop.
- Media2 text OSD and polygon privacy masks are scoped to their source
  configuration. Writes support independent read-back. A lost reply can
  produce `OutcomeUnknown`, so read the current state before retrying.
- Read or update supported Media1/Media2 audio configurations, read
  Analytics modules and rules, parse metadata XML, search the recording
  timeline and events, and manage remote export jobs. The optional
  `talkback` feature sends one half-duplex PCMU track. The optional
  `recording-download` feature downloads from an explicit URL and
  preserves existing destination files.

## Mock and replay

- Raw HTTP fixtures should send SOAP 1.2 `application/soap+xml` with a
  valid action parameter for dispatch. Malformed headers can return HTTP
  400 and unsupported representations return 415. Recognized SOAP
  Sender faults use HTTP 400, and other standard SOAP fault codes use 500.
  Legacy nonstandard fault codes and malformed raw responses use 200.
- Create a PullPoint before emitting test events and use the returned
  endpoint for pulling, renewing and unsubscribing. With mock authentication
  enabled, generate fresh UsernameTokens for successive positive requests.
- Recording searches now have isolated snapshots, pagination and expiry.
  `EndSearch` releases the search, and unknown or expired tokens return
  a fault. Media1 and Media2 share mock OSD state. Privacy masks belong
  to the individual mock instance.
- Metamorph compares reviewed fields for 16 SOAP Actions and can compare
  ordered event windows. Search and PullPoint lifecycle calls use live
  state during replay.

## Dependencies and verification

The workspace lockfile uses `tokio-rustls 0.26.6`,
`rustls-native-certs 0.8.5` and `tokio 1.54.1`. Library users control
their application's lockfile and can update these dependencies there.
Native credential storage uses `keyring 3.6.3`. The local dependency
audit found zero vulnerabilities and three existing maintenance warnings
in the Linux credential dependency graph.

On Windows, each dependency batch passed 1,496 all-feature and 1,352
default-feature workspace tests and the Rust 1.88 workspace check. The
combined lockfile passed strict Clippy. ONVIF workflows were checked with
local loopback services, synthetic fixtures and ONVIF schemas. Camera and
firmware validation is pending.
