## CLI 與自動化

- **指定媒體服務。** 使用 `--media-service media1`、`media2` 或
  `auto` 查詢 Profile、URI、診斷、設定清冊及健康檢查中的媒體資訊。
  `auto` 優先嘗試裝置宣告的 Media2，缺少端點或裝置明確回報不支援操作時
  回退至 Media1。省略旗標時，`media profiles` 使用 Media1，
  `data.result` 是陣列。明確指定服務後，`data.result` 是含
  `profiles`、`media_service`、`endpoint_source` 和 `attempts` 的物件。
  兩種格式的 JSON／JSONL 外層均使用 schema v3。
- **依裝置選擇 SOAP 認證。** `--soap-auth` 支援 `combined`（預設）、
  `digest` 和 `ws-security`。自動時鐘同步會在使用 WS-Security
  UsernameToken 時讀取裝置時間。
- **按需探測串流。** 使用 `oxvif --rtsp-probe describe diagnose CAMERA`
  查看 SDP 與宣告的影像 codec。`packet` 另執行 SETUP、PLAY、等待一個
  interleaved 影像 RTP 封包，並嘗試 TEARDOWN。兩種模式的
  `playback_verified` 都是 `false`。串流須使用與裝置相同的 host，
  HTTPS 裝置 URL 須使用 RTSPS 並驗證憑證。
- **查看完整的健康檢查。** `oxvif health check --details` 在終端顯示每項
  檢查及耗時。`-vv` 將有界的 Session 與重試診斷寫入 stderr。
  JSON／JSONL 報告均包含完整檢查項目。

參閱 [CLI 指南](../oxvif-cli_zh.md)。

## Rust 升級注意事項

以下事項適用於從 0.17.1 升級。

- **處理未完成的錄影搜尋。** 搜尋因上限、取消或未知狀態在 Completed 前
  結束時，`search_recordings()` 回傳 `OnvifError::RecordingSearchIncomplete`。
  RPC 失敗會傳回原本的錯誤。需要保留部分錄影結果、失敗原因和獨立的
  `EndSearch` 結果時，請改用 `search_recordings_with_report()`。
  持有搜尋資源時請明確呼叫 `close()`，以清理遠端搜尋。
- **更新窮舉 `match`。** 加入 `OnvifError::RecordingSearchIncomplete`、
  `TransportError::Deadline`、`TransportError::ResponseTooLarge`、
  `SoapError::ResourceLimit` 和
  `HttpTransportBuildError::{InvalidTimeout, InvalidResponseLimit}`。
  使用完整 struct literal 建立 CLI 函式庫的 `ExecutionOptions` 時，
  須設定 `soap_auth`、`media_service` 和 `rtsp_probe`。可用
  `..Default::default()` 初始化採預設值的欄位。
- **檢查正式 SOAP 流程使用的 fixture 和自訂 Transport。** 回應須為完整
  XML，限制為 4 MiB、深度 64 和 65,536 個元素，亦適用於自訂 Transport
  的回應。內建 HTTP Transport 預設每個 HTTP 請求限時 10 秒，回應上限
  4 MiB。有指定端點範圍的操作可以限制整次 SOAP 交換時間，包含 Digest
  challenge 與重送。
- **查核傳輸內容時使用明確的擷取流程。** 用戶端 trace 現在記錄操作名稱、
  耗時、位元組數和錯誤類別。需要檢查傳輸內容時請明確擷取，分享前檢查
  其中的裝置資料。

參閱 [Rust 函式庫指南](../../LIBRARY_GUIDE_zh.md)。

## Rust 新功能

- 受管理的 PullPoint 保留具 namespace 的 topic 與端點參數，可在輪詢
  期間續租，恢復後回報事件缺口，並支援非同步關閉。
- 型別化 PTZ 支援分開指定 pan/tilt 和 zoom，並可設定座標空間、速度、
  持續移動的 timeout 和分軸 Stop。
- Media2 文字 OSD 與多邊形隱私遮罩綁定來源組態，寫入後可獨立讀回。
  遺失回覆時可能得到 `OutcomeUnknown`，重試前可先讀取現況。
- 可讀取或修改受支援的 Media1／Media2 音訊組態、讀取 Analytics 模組與
  規則、解析 Metadata XML、查詢錄影時間軸和事件，以及管理遠端匯出。
  選用的 `talkback` feature 支援單軌 PCMU 半雙工送出。
  `recording-download` 可從明確指定的 URL 下載，並保留已存在的目的地檔案。

## Mock 與 replay

- 直接送 HTTP 的 fixture 應使用 SOAP 1.2 `application/soap+xml`，並帶上供
  路由使用的有效 action 參數。標頭格式錯誤可回 HTTP 400，不支援的格式回
  415。可辨識的標準 Sender Fault 回 HTTP 400，其他標準 SOAP Fault 回
  500。既有非標準 Fault 和格式錯誤的原始回應使用 200。
- 在送出測試事件前建立 PullPoint，並使用回傳的端點拉取、續租和取消訂閱。
  啟用 Mock 認證時，每次預期成功的請求須產生新的 UsernameToken。
- 錄影搜尋有獨立快照、分頁及到期機制。`EndSearch` 釋放搜尋，未知或過期
  token 會回 Fault。Media1 和 Media2 共用 Mock OSD，隱私遮罩歸各 Mock
  instance 所有。
- Metamorph 比較 16 個 SOAP Action 中已審查的欄位，也能比較有順序的
  事件視窗。重播時，搜尋和 PullPoint 生命週期操作由即時狀態處理。

參閱 [Mock 伺服器指南](../mock-server_zh.md)與
[互通性驗收紀錄](../active/onvif-interoperability-plan_zh.md#i07i10-交付證據)。

## 相依套件與驗收

Workspace 的 lockfile 使用 `tokio-rustls 0.26.6`、
`rustls-native-certs 0.8.5` 和 `tokio 1.54.1`。函式庫使用者可在自己的
應用程式 lockfile 更新這些套件。原生憑證儲存使用 `keyring 3.6.3`。
本地相依套件稽核未發現漏洞，Linux 憑證相依套件仍有三則既有維護警告。

兩批相依套件更新均在 Windows 通過 1,496 個全功能及 1,352 個預設功能的
workspace 測試，以及 Rust 1.88 的 workspace 編譯檢查。合併後的鎖檔通過
嚴格 Clippy。ONVIF 流程已用本地 loopback、合成 fixture 與 ONVIF schema
驗證。攝影機與韌體的實機驗收待後續進行。

參閱[完整變更紀錄](../../CHANGELOG.md#unreleased)。
