## CLI workflows

### Maintenance

- `oxvif manage` provides a human-terminal workspace retaining camera/profile
  context across diagnosis, snapshot saving and configuration inspection/comparison.
  Sessions are reused for at most 60 seconds and invalidated after failure or
  cancellation. Session-only credentials do not replace saved credentials.
- `snapshot --save` and `media snapshot-save` download size-limited images to
  new files. Existing destinations are not overwritten. Download URL, redirect,
  authentication, TLS, timeout, image-signature and cancellation checks remain
  distinct from successful media decoding.
- `diagnose` produces staged, summary-first reports; `-v` shows details.
  Earlier results remain available if a later stage fails. Multiple profiles
  require explicit selection or a paginated human picker, not a guessed profile.
- `config export` and `config diff` create versioned read-only settings
  inventories and JSON Pointer differences. Partial sections are incomparable;
  exports are not restorable backups. File workflows are single-device.
- Maintenance root selectors/execution options work before or after commands.
  Human progress does not contaminate structured stdout. Profile reports expose
  optional configured encoding/resolution/FPS and explicit detail availability;
  these are camera-reported settings, not measured stream properties.
- Diagnosis reports observed failures, dependent untested checks and unimplemented
  limitations. A timeout is not a proven authentication root cause. Cancellation
  of a profile preflight stops the requested workflow rather than starting a
  subsequent diagnostic request.

### Navigation and compatibility

- `?` offers line-number settings and contextual key bindings, switched with Tab.
  Help is read-only, scrollable and tailored to the originating screen; closing it
  retains the caller's view and does not apply an unconfirmed preference.

- Manage and standalone discovery lists fill the available terminal height, removing
  the 12-row ceiling. Resizing preserves visible selection and bottom help/status;
  full/half-page movement follows the current viewport capacity.

- Discovery setup stays inline through retry and consecutive additions; manage
  separates Enter/select from explicit `a`/save without changing global current.
  Saved-list search keeps network/address actions reachable with no matches.
- Up to 256 isolated camera workspaces retain temporary credentials, profile and
  result/menu state across switching; changed saved records invalidate old state.
  Profile reads remain live and restore by token, not by a stale list position.
- Separate historical failure/cancellation reports, searchable persistent report
  views, non-secret editable drafts and last-successful-export baseline selection
  complete the workflow continuity batch. No Agent envelope changes.

- Returning to `manage` discovery restores session-cached results, text/registration
  filters, selection and scroll position. Uppercase `R` explicitly rescans; success
  resets the view, while cancellation or failure preserves it. The cache ends with
  `manage`; standalone `discover` remains a fresh scan on each invocation.
- `manage` network results share the `discover` browser: `/` searches,
  `r`/`n` filter saved/unregistered records, `A` resets only the registration
  filter, and `c` clears text. Enter selects the original matching record;
  new cameras remain session-only and are not registered automatically.
- Human table reports, verbose details, errors and line-oriented profile menus
  escape terminal control and bidirectional formatting characters. Structured
  JSON/JSONL values remain unchanged; display escapes are not identifiers.
  Full-screen menus and text also escape directional formatting controls before
  width measurement, truncation and wrapping.
- The shared backend-free navigation core supports counted `j`/`k`,
  `gg`/`G`, absolute `nG`/`ngg`, and Ctrl+D/Ctrl+U half-page movement.
  A fixed-bottom reverse-video NORMAL/INPUT/SEARCH/BUSY bar is separate from
  hints, shows pending input only while active, and retains position, available
  context and elapsed BUSY time. Manage menu positions survive returns/cancellation.
  Discovery's former single `g` becomes `gg`; Home remains available.
- `--line-numbers absolute|relative|hybrid|off` selects numbering for an
  invocation. `?` previews/applies session preferences or explicitly saves
  `ui-preferences.json`; hybrid remains the default. Numbers are navigation
  aids, not persistent device identities.
- Headings/content/hints are separated by horizontal rules. Camera columns align
  across pages and remain bounded with long names. Narrow terminals prioritize
  content; path editing scrolls horizontally and preserves input after errors.
- Input/search fields retain literal typing and Ctrl+U clearing. Recognized paste
  events do not execute navigation; legacy terminals reporting paste as keystrokes
  remain a limitation. Human controls do not alter JSON/JSONL output.
- Windows debug CLI startup stack use is reduced by heap-pinning dispatch futures.
  Output tests exclude variable timing from equality while still validating its
  field and all functional metadata; the runtime JSON contract is unchanged.

### Agent results

Agent guide v8 documents additive profile-selection reasons/candidates, retained
failure reports and untested-stage reasons. Envelope schema v3 is retained.
`manage` is terminal-only; Agents use the underlying commands without menus.

| Result | Exit / interpretation |
| --- | --- |
| Completed snapshot/export/diagnosis | 0; inspect report limitations |
| Complete equal or different comparison | 0; inspect `matches` and `changes` |
| Incomplete/failed maintenance report | 20; report can remain in `data.result` |
| Partly successful fleet diagnosis | 6; preserve per-device reports |
| All fleet diagnosis failed | 20; retain diagnosis results |
| Existing destination | 4; do not overwrite |
| Invalid baseline/identity/unsupported selector | 2; no comparison or replacement |

Existing credential/file/connection codes still apply. These new workflows do not
redefine older command exits. `snapshot` conservatively declares local-file write
risk; `mutates_device` remains false and `media snapshot-uri` stays URI-only.
See the [operator and Agent guide](../cli-maintenance.md) for exact fields and examples.

## Library changes

- `notification_listener_with_peer` returns `ReceivedNotification`, pairing
  the unchanged notification message with the TCP `SocketAddr`. The async
  listener reports bind errors and is bound when it returns. The legacy listener,
  message struct literals and JSON remain compatible. Dropping either stream
  cancels its owned connection tasks; it does not unsubscribe a remote camera.
  Proxy headers are not trusted. Peer address is not authenticated camera identity
  and is never inserted into ONVIF notification XML. Adapted with credit to PR #17.
- Client/session methods `media_set_synchronization_point` and
  `set_synchronization_point_media2` request synchronization for streams
  associated with an explicit profile. Service Actions/endpoints stay separate;
  there is no implicit fallback to Events or Media1. A SOAP receipt does not prove
  I-frame or metadata delivery. Adapted with credit to PR #16;
  see [media synchronization](../media-synchronization.md).
- Full Media2 profile enumeration now explicitly requests `Type=All`, ensuring
  conforming devices can return associated configurations rather than profile
  identity alone.
- Media2 fractional frame rates are preserved rather than silently parsed as zero.
  Missing rate control remains absent; malformed present blocks and nonfinite or
  negative values error. Audio options read all repeated integer Items, retaining
  compatibility with legacy whitespace-separated lists.
- Metadata models preserve structured multicast and session timeout; setters
  include required modeled fields and preserve IPv4/IPv6 address family.
- Shared XML escaping uses references for CR/LF/tab, preserving literal data
  through XML text/attribute normalization. Bytewise fixtures may need updating.

## Mock contracts

This is a selected migration, not a complete ONVIF device implementation.

| Area | Included contract / remaining boundary |
| --- | --- |
| Common requests | Bounded namespace-aware parsing and exact Action/body identity, including static reads; malformed or ambiguous containers fail before synthetic handlers. HTTP rejects invalid UTF-8 with 400 / Sender / mock:RequestPolicy before the responder chain, without repairing request values. Valid Unicode remains supported; full HTTP binding remains under review |
| Faults/auth | Structured selected SOAP faults, bound prefixes and literal reason escaping. Opt-in auth reads unique qualified Header/UsernameToken fields, explicit digest/nonce encoding and fixed non-reflecting errors; freshness, nonce reuse and roles are not implemented |
| Profiles | Decoded literal names/tokens, one-time escaping, scoped selectors, `Type` selection, duplicate/collision-safe generated tokens and eight-profile creation limit without truncating imported fixtures |
| Binding | Atomic complete candidate, initial Media2 bindings, rename-only updates, supported All semantics, slot conflict/ref checks and touched use counts; unsupported binding kinds are not silently advertised as implemented |
| Source | Scoped complete settings, actual source limits and generic/profile selectors; unmodeled offsets/extensions refuse; rejected writes preserve state and recordings |
| Encoder/rate | Complete scoped candidate, advertised combinations and explicit adaptation; fractional rates retained, Media1 refuses incompatible views, H265 does not leak into Media1 |
| Audio/metadata | Service-specific codec vocabulary, complete modeled candidate, repeated options, multicast/session fields and read-only AutoStart; not a lossless editor for unsupported metadata extensions |
| Snapshots/hooks | Profile/configuration reads share a state snapshot; hooks receive the committed snapshot outside the lock. Separate requests are not transactional; callback order is caller-managed |
| PTZ/adapter identity | Nineteen existing PTZ profile/head consumers preserve scoped literal identity. Other motion/configuration/tour semantics are not claimed complete |
| Effects | Thirteen classified operations refuse by default; exact-operation acknowledgment opt-in permits only a response, never reset, motion, subscription lifetime or media delivery |

The receipt-only set covers reset, Device/PTZ auxiliary commands, reboot, upgrade,
restore, Events subscribe/renew/unsubscribe/synchronization, EndSearch, and
Media1/Media2 synchronization. These selections do not change state, call hooks or
retire replay reads. Reboot text explicitly says no reboot occurred; upload URIs,
subscription references and timestamps are fixture data. Media synchronization
additionally validates its unique scoped profile. Events remains a separate policy.

See [Mock reference](../mock-server.md), [operation cards](../active/mock-fidelity-operation-ledger.md)
and the [receipt policy](../active/mock-fidelity-ack-policy-preflight.md).
Do not interpret every implemented client operation as a faithful simulated effect.

## Metamorph and recorded data

- Selected profile create/delete/binding, source, encoder and audio/metadata
  writes retire dependent recorded reads only after a successful synthetic commit.
  Refusals and fault/auth short circuits retain recordings. Complete dependency
  tracking and concurrent visibility remain open.
- **K27 storage repair:** canonical keys select collision buckets. Distinct
  requests survive recording, load/save and replay; only equivalent requests
  replace each other. Built-in replay selects a unique scoped request identity.
  Unconfirmed matches fall through; exact raw recordings and qualified header
  ephemera remain supported. Previously lost records cannot be recovered.
- Key-only `lookup` returns `None` for ambiguous buckets; use `lookup_request`.
  Reports retain colliding rows. `QuirkDiff` cannot pair ambiguous legacy rows,
  so retains them as unmatched `appeared`/`resolved` observations, not evidence
  of introduced/fixed defects. See [storage and report migration](../replay-storage.md).
- URL `user:pass@` pairs are removed from canonical keys and value projections,
  including XML-decoded values. Legacy key cleanup is in-memory on load; explicit
  save persists it. Only equivalent requests in the same bucket use the last entry. Review old
  files/backups before sharing; raw redaction is targeted, not a general detector.
- Typed adapters require exact supported Action/qualified operation and preserve
  token identity. Unsupported PTZ representations fall through to explicit raw/
  synthetic handling rather than invoking typed hooks with discarded arguments.
  Trait signatures and raw escape-hatch input/output remain unchanged.
- Recorded write receipts are excluded for classified acknowledgment-only
  operations. Explicit fault injection and caller-owned adapter raw responses are
  separate controls; neither establishes synthetic or physical correctness.

## Breaking changes and migration

| Surface | Upgrade action |
| --- | --- |
| `VideoRateControl2.frame_rate_limit`, `mock::VideoEncoderState.frame_rate_limit` | Change `u32` assumptions to `f32`, e.g. `25` → `25.0`; do not truncate fractional rates. Integer JSON is accepted but output may be fractional |
| `MetadataConfiguration` / `mock::MetadataEntry` | Replace flattened multicast fields with the structured multicast value and session timeout. Obtain missing TTL/AutoStart/timeout from known complete data, not invented defaults |
| Raw Mock fixtures | Supply scoped operation/field identities and complete modeled candidates. Do not repair a failing test by making unknown inputs return success |
| Fault matching | Selected operations now use SOAP Sender/Receiver plus nested subcodes. Client `subcode` exposes the first level, not the deepest condition; update flat-code assumptions |
| Unmodeled effects | Expect default `mock:UnmodeledEffect`; explicitly opt in only when testing a receipt, not the effect |
| Stored snapshots | Review literal tokens, empty seeded identities, fractional Media1 views and metadata completeness. No automatic snapshot rewrite/repair is promised |
| Recorded fixtures and report joins | Use request-aware lookup for collisions, not the key pair as a unique row ID. Back up before downgrade: older readers can collapse buckets even though JSON remains readable |
| Human navigation | Replace single `g` with `gg`; numbering preferences do not change saved IDs or Agent contracts |

For example, retain the requested fraction in Rust:

```rust
use oxvif::VideoRateControl2;
let rate = VideoRateControl2 {
    frame_rate_limit: 12.5,
    bitrate_limit: 2048,
};
assert_eq!(rate.frame_rate_limit, 12.5);
```

For a receipt-only Media1 mock test:

```rust
use oxvif::mock::{AckOnlyOperation, MockTransport};
let transport = MockTransport::new()
    .with_acknowledgment_only(AckOnlyOperation::MediaSynchronizationPoint);
```

Detailed migration examples: [frame rates](../media2-frame-rate.md),
[audio and metadata](../audio-metadata.md), [profile assembly](../active/mock-fidelity-profile-assembly.md).
Metadata remains a modeled subset; a real-camera read-modify-write cannot preserve
unrepresented vendor/event/filter settings.

## Verification and limitations

Historical combined Windows development batch, recorded in `6cf345c`: **1,316 passed,
0 failed, 6 ignored** with all features; **1,204 passed, 0 failed, 6 ignored** with
default features. Both Clippy/strict rustdoc modes and formatting passed. Three
example tests and the 64/256-device loopback capacity smoke passed separately;
they are not added to the workspace totals. See the [ignored-test breakdown](../active/mock-fleet-basic-plan.md#ignored-tests).
The six exclusions include two unverified documentation snippets. This is not
native LAN/VMS, new hosted CI, MSRV rerun or final-release acceptance. The following
older results retain their original scope; they are not overwritten by these totals.

Pre-version review adds direct integer-rate encoder replay controls over
in-process and HTTP transports, complementing existing fractional-rate tests.
These verify retained recordings after refusal, six refreshed views after a
Media2 commit and two unaffected recording controls. See the
[review evidence](../active/release-0.17-review.md#v01-encoder-replay-coverage);
this is not a new production fix or complete replay-conformance acceptance.

The shared snapshot repair replaces the separate CLI/health download paths.
HTTP/1.1 title-case field names address the demonstrated firmware incompatibility;
Digest parameters retain standard quoting. Health no longer falls back to Basic
after Digest failure and now shares the 16 MiB, same-host, no-redirect/no-proxy,
no-HTTPS-downgrade and total-deadline policies. Its new
`with_snapshot_options` builder configures snapshot-only CA roots and deadlines.
Challenge parsing handles scheme/parameter case, quoted lists, supported
alternatives and empty-GET auth-int; one same-policy stale retry is permitted.

Regression fixtures now verify the actual Digest response before returning a
synthetic JPEG. Wrong credentials and tampered digests are rejected. Signature
recognition is not decoding; PNG/BMP remain non-ONVIF compatibility extensions.
The earlier qop explanation in published 0.15 history is not the demonstrated
cause of this batch's 401 failures. The repaired candidate's measured results
and remaining gates are tracked in the
[snapshot batch](../active/snapshot-auth-repair.md) and
[approval packet](../active/release-0.17-approval.md).

The pre-version review also fixes snapshot Digest Authorization quoting: `qop`
remains an unquoted token, as required by RFC 7616 section 3.4. It is not rewritten
using WWW-Authenticate's quoted-list syntax. No credential, TLS, redirect or
authentication-downgrade policy is relaxed. See the
[maintenance guide](../cli-maintenance.md#snapshot-download).
