# oxvif 0.17.0 / oxvif-cli 0.17.0

[English](0.17.0.md) | [繁體中文](0.17.0_zh.md)

此頁為文件庫中的繁中對照；GitHub Release 本文僅使用英文版。

發布日期：2026-09-14。

主旨：**探索、診斷與維護攝影機，不必重新開始 CLI 工作流程。**
0.17 新增連續維護工作區、快照存檔及設定比較，並改善終端導覽的一致性與
快照相容性。Agent 可透過結構化命令使用相同維護操作。

### 新增

- **`oxvif manage`：整合攝影機維護工作區。** 選擇已儲存的攝影機，或從網路探索，
  再選擇 Media Profile，即可接續診斷、保存快照及檢視設定，不必重複輸入裝置 ID。
  切換攝影機或返回操作時，保留本次工作階段中各攝影機的 Profile、結果及選單狀態。

- **`oxvif diagnose`：保留實際證據的分階段報告。** 以摘要檢視裝置、Profile、URI
  及快照檢查，搭配 `-v` 查看細節。後續檢查失敗時，已完成階段仍然保留；
  存在多個 Profile 時要求選擇，不會自行代選串流。

- **直接保存快照檔案。** `oxvif snapshot CAMERA --save image.jpg` 下載辨識為圖片的
  內容，不再僅回傳 URI。下載設有大小上限，且不覆寫既有目的地檔案。

- **匯出並比較攝影機設定。** `oxvif config export CAMERA --save settings.json`
  產生唯讀設定清冊；`oxvif config diff CAMERA --against settings.json`
  與攝影機目前設定比較。報告區分實際差異與無法比較的區段。

### 修正

- **返回探索結果不再需要重新掃描。** 在 `manage` 內切換畫面時，保留探索結果、
  文字與已儲存／新裝置篩選、選取項目及捲動位置。`R` 明確重新掃描；
  掃描失敗或取消時保留先前結果。

- **新增攝影機維持在同一介面。** 畫面內設定支援重試及連續新增。
  選取新發現的攝影機不會自動儲存；使用 `a` 明確驗證並儲存。

- **改善受影響韌體的快照認證相容性。** CLI 與 health 共用下載器，處理已重現的
  HTTP 標頭大小寫差異，同時保留 Digest 認證、TLS 驗證及重新導向安全限制。
  非圖片回應仍回報失敗。

### 調整

- **一致且可設定的終端導覽。** 清單依視窗高度展開，支援數字前綴 `j/k`、
  `gg/G`、PgUp/PgDn 與 Ctrl+D/U，並提供獨立底部狀態列。`?` 分別顯示行號設定及
  情境按鍵說明，可選擇絕對、相對、混合或不顯示行號。

- **人類與 Agent 工作流程共用維護證據。** JSON／JSONL 命令提供 Profile 選擇原因、
  部分結果及未測項目，不會開啟互動選單。Agent guide v8 說明這些流程；
  envelope schema 維持 v3。

### 不相容變更與限制

- Library 使用者須處理 Media2 幀率改為 `f32`，以及 metadata multicast／
  session-timeout 欄位結構化等變更。升級既有應用程式或測試 fixture 前請先閱讀遷移指南。
- 設定匯出**不是可還原備份**；診斷**不驗證 RTSP 播放或影片解碼**。

### 驗證

0.17 候選已通過 Windows、Linux、macOS CI，以及不發布的 APT／Homebrew 安裝
staging。這些驗證不代表已收錄至官方套件庫；精確證據及剩餘限制記於完整文件。
