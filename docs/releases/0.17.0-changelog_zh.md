## CLI 工作流程

### 維護

- `oxvif manage` 提供人類終端工作區，在診斷、儲存快照及設定檢視／比較之間
  保留攝影機與 profile 上下文。Session 最多重用 60 秒，失敗或取消後失效。
  僅限 session 的憑證不取代已儲存憑證。
- `snapshot --save` 及 `media snapshot-save` 在大小限制內下載影像至新檔案，
  不覆寫既有目的檔。下載 URL、redirect、認證、TLS、timeout、影像 signature
  及取消檢查，不等同於影像成功解碼。
- `diagnose` 產生分階段、摘要優先的報告；`-v` 展開細節。後續階段失敗仍
  保留先前結果。多個 profile 須明確指定或使用分頁選單，不猜測目標。
- `config export`／`config diff` 提供版本化唯讀設定清冊與 JSON Pointer
  差異。未完整取得的區段不比較；匯出不是可還原備份。檔案流程限單一裝置。
- 維護命令的根層 selector／執行選項可放在命令前後。人類進度不污染結構化 stdout。
  Profile 報告增加可選的 encoding／resolution／FPS 及明確細節可用性，
  這些是攝影機回報設定，不是實測串流值。
- 診斷區分觀察到的失敗、相依而未測的階段及未實作限制。Timeout 不代表已證明
  帳密是根因。取消 profile 前置選擇會停止整個流程，不再啟動下一項診斷請求。

### 導覽及相容性

- 人類表格、詳細報告、錯誤輸出及逐行 profile 選單，會轉義終端控制與雙向文字
  格式控制字元。JSON／JSONL 資料值不變；畫面上的跳脫表示不作為識別碼。
  全螢幕選單及文字亦於量測欄寬、截斷及換行前轉義雙向格式控制字元。
- 共用且不依賴終端後端的核心支援帶次數的 `j`／`k`、`gg`／`G`、
  絕對 `nG`／`ngg` 及 Ctrl+D／Ctrl+U 半頁移動。
  NORMAL／INPUT／SEARCH／BUSY 精簡狀態列顯示待完成輸入及位置。
  Discovery 原本單一 `g` 改為 `gg`；Home 仍可使用。
- `--line-numbers absolute|relative|hybrid|off` 設定本次執行的行號；
  `?` 可預覽／套用 session 設定，或明確儲存至 `ui-preferences.json`。
  預設仍為 hybrid。行號只協助導覽，不是永久裝置身分。
- 標題、內容及提示以水平線分隔。攝影機欄位跨頁對齊，長名稱不會無限制擠壓
  其他欄位。窄終端優先顯示內容；路徑編輯支援水平捲動，錯誤後保留輸入。
- 輸入／搜尋欄位保留一般文字輸入及 Ctrl+U 清除。可識別的 paste event 不執行
  導覽；將貼上視為連續按鍵的舊終端仍有限制。人類控制不改動 JSON／JSONL。
- Windows debug CLI 以 heap-pinning dispatch future 降低啟動 stack 使用。
  輸出測試將變動時間排除於相等比較，但仍驗證時間欄位與全部功能性 metadata；
  runtime JSON 契約不變。

### Agent 結果

Agent guide v8 記載新增的 profile selection reason／candidate、失敗報告保留
及未測原因。Envelope schema 維持 v3。`manage` 限人類終端；
Agent 使用底層命令，不開選單。

| 結果 | Exit／判讀 |
| --- | --- |
| snapshot／export／diagnosis 完成 | 0；仍須檢查報告限制 |
| 完整比較，相同或不同 | 0；檢查 `matches` 及 `changes` |
| 維護報告未完成／失敗 | 20；報告可能保留於 `data.result` |
| Fleet diagnosis 部分成功 | 6；保留各裝置結果 |
| Fleet diagnosis 全部失敗 | 20；保留診斷結果 |
| 目的檔已存在 | 4；不覆寫 |
| baseline／identity 無效或 selector 不支援 | 2；不比較或替換檔案 |

既有憑證／檔案／連線錯誤碼仍適用；新增流程不重新定義舊命令 exit。
`snapshot` 保守宣告本機檔案寫入風險，但 `mutates_device` 仍為 false；
`media snapshot-uri` 仍只取得 URI。精確欄位及範例見
[操作與 Agent 指南](../cli-maintenance_zh.md)。

## Library 變更

- `notification_listener_with_peer` 回傳 `ReceivedNotification`，將未變動
  的通知訊息與 TCP `SocketAddr` 配對。非同步 listener 回傳 bind 錯誤，
  成功回傳時已完成綁定。舊 listener、訊息 struct literal 及 JSON 維持相容。
  丟棄任一 stream 會取消其所屬 connection task，但不對遠端攝影機 unsubscribe。
  不信任 proxy header；peer 不代表已驗證的攝影機身分，也不加入 ONVIF XML。
  改寫自 PR #17 並保留署名。
- Client／Session 的 `media_set_synchronization_point` 及
  `set_synchronization_point_media2` 請求明確 profile 的關聯串流同步。
  各 service 的 Action／endpoint 分開，不隱含 fallback 至 Events 或 Media1。
  SOAP 收件確認不能證明 I-frame 或 metadata 已傳送。改寫自 PR #16 並保留署名；
  見 [Media 同步](../media-synchronization_zh.md)。
- Media2 完整 profile 列舉明確傳送 `Type=All`，使符合協議的裝置可回傳關聯
  configuration，而不只回傳 profile identity。
- Media2 保留小數 frame rate，不再默默解析為零。缺少 RateControl 維持 absent；
  存在但格式不正確、非有限或負值會回傳錯誤。Audio options 讀取每個重複整數
  Items，並維持舊空白分隔清單的相容性。
- Metadata 模型保留完整 multicast 及 session timeout；setter 傳送必需建模欄位，
  保留 IPv4／IPv6 address family。
- 共用 XML escaping 對 CR／LF／tab 使用 character reference，保留 XML
  文字／attribute 正規化後的 literal data；逐 byte 比對的 fixture 可能須更新。

## Mock 契約

本版是選定子群的遷移，不是完整 ONVIF 裝置實作。

| 面向 | 收錄契約／保留邊界 |
| --- | --- |
| 共用 request | 有資源上限的 namespace-aware parser 及精確 Action／body identity，包含靜態讀取；格式錯誤或歧義容器在 synthetic handler 前拒絕。HTTP 在 responder chain 前以 400／Sender／mock:RequestPolicy 拒絕無效 UTF-8，不修補請求值。合法 Unicode 仍受支援；完整 HTTP binding 仍待審 |
| Fault／auth | 選定 structured SOAP fault、prefix 綁定及 literal reason escaping。Opt-in auth 讀取唯一 qualified Header／UsernameToken、明確 digest／nonce encoding，使用不反射輸入的固定錯誤；未實作 freshness、nonce reuse 或角色授權 |
| Profile | 解碼的 literal name／token、單次 escaping、scoped selector、Type 選擇、防止重複／碰撞的產生 token，以及八個 profile 的建立上限；不截斷匯入 fixture |
| Binding | 原子完整候選、Media2 初始 binding、僅改名、支援的 All 語意、slot 衝突／reference 檢查及受影響 use count；不默默將未支援 binding 宣告為已實作 |
| Source | Scoped 完整設定、實體 source 限制及 generic／profile selector；未建模 offset／extension 拒絕；失敗保留 state 及 recording |
| Encoder／rate | 完整 scoped 候選、advertised combination 及明確 adaptation；保留小數，Media1 拒絕無法呈現的 view，H265 不滲入 Media1 |
| Audio／metadata | 各服務 codec vocabulary、完整建模候選、重複 options、multicast／session 欄位及唯讀 AutoStart；不是保留全部 metadata extension 的無損編輯器 |
| Snapshot／hook | Profile／configuration 讀取共用 state snapshot；hook 在鎖外接收 committed snapshot。不同 request 不構成 transaction；callback 順序由 caller 管理 |
| PTZ／adapter identity | 十九個既有 PTZ profile／head 使用端保留 scoped literal identity；不宣稱其他 motion／configuration／tour 語意已完成 |
| 效果 | 十三個已分類操作預設拒絕；精確操作 opt-in 只允許回應，不代表 reset、移動、subscription lifetime 或 media delivery |

僅收件確認集合包含 reset、Device／PTZ auxiliary command、reboot、upgrade、
restore、Events subscribe／renew／unsubscribe／synchronization、EndSearch，
以及 Media1／Media2 synchronization。這些選擇不改 state、不呼叫 hook、不淘汰
replay 讀取。Reboot 文字明確說明未重啟；upload URI、subscription reference
及 timestamp 是 fixture 資料。Media synchronization 額外驗證唯一 scoped profile；
Events 維持獨立政策。

參閱 [Mock 參考](../mock-server_zh.md)、[操作工作卡](../active/mock-fidelity-operation-ledger_zh.md)
及[收件政策](../active/mock-fidelity-ack-policy-preflight_zh.md)。
Client 操作已實作，不代表其效果已被忠實模擬。

## Metamorph 與錄製資料

- 選定 profile create／delete／binding、source、encoder 及 audio／metadata
  寫入，只有在 synthetic commit 成功後才淘汰相依 recorded read。
  拒絕及 fault／auth short circuit 保留 recording。完整相依及併發可見性仍待完成。
- **K27 儲存修正：** canonical key 改為選取碰撞群組。錄製、載入、保存與 replay
  均保留不同請求，只有等價請求互相替換。內建 replay 選取唯一 scoped request
  identity；無法確認時 fallback。精確 raw recording 與 qualified header
  ephemera 仍受支援；舊版已遺失的資料無法恢復。
- 僅提供 key 的 `lookup` 在歧義時回傳 `None`，請使用 `lookup_request`。
  報告保留碰撞列；`QuirkDiff` 無法配對具有歧義的 legacy 列，因此完整保留為
  未配對的 `appeared`／`resolved` 觀察值，不代表新增／修復缺陷。
  詳見[儲存與報告遷移](../replay-storage_zh.md)。
- Canonical key 及 value projection 移除 URL `user:pass@`，包含 XML 解碼
  後的值。Legacy key 載入時只在記憶體清理，明確 save 才保存；只有同群組的等價
  請求採最後存入項目。分享前應檢查舊檔／備份；raw redaction 不是通用機密偵測器。
- Typed adapter 要求精確支援的 Action／qualified operation 並保留 token 身分。
  無法表示的 PTZ 請求改交明確 raw／synthetic fallback，不以丟失參數的形式
  呼叫 typed hook。Trait signature 及 raw 逃生出口的 input／output 不變。
- 已分類 acknowledgment-only 操作不直接重播錄製的寫入確認。明確 fault
  injection 及 caller-owned adapter raw response 是獨立控制，不證明
  synthetic 或實體行為正確。

## 不相容變更與遷移

| 面向 | 升級方式 |
| --- | --- |
| `VideoRateControl2.frame_rate_limit`、`mock::VideoEncoderState.frame_rate_limit` | 將 `u32` 假設改為 `f32`，例如 `25` → `25.0`，不可截斷小數。接受整數 JSON，但輸出可能含小數 |
| `MetadataConfiguration`／`mock::MetadataEntry` | 扁平 multicast 欄位改為結構化 multicast 及 session timeout。缺少 TTL／AutoStart／timeout 時取得已知完整資料，不虛構預設值 |
| Raw Mock fixture | 提供 scoped operation／field identity 及完整建模候選；不以讓未知輸入成功的方式修復測試 |
| Fault 比對 | 選定操作改用 SOAP Sender／Receiver 及巢狀 subcode。Client `subcode` 是第一層而非最深層，須更新 flat-code 假設 |
| 未建模效果 | 預期預設 `mock:UnmodeledEffect`；只有測試收件而非效果時才明確 opt-in |
| 儲存快照 | 檢查 literal token、空 seeded identity、Media1 小數 view 及 metadata 完整性；不承諾自動改寫／修復 |
| 錄製 fixture 與報告關聯 | 碰撞時使用完整請求查詢，不將 key pair 當作唯一列 ID。降版前備份：JSON 雖仍可讀，舊版仍可能合併群組 |
| 人類導覽 | 單一 `g` 改為 `gg`；行號設定不改儲存 ID 或 Agent 契約 |

例如在 Rust 保留要求的小數值：

```rust
use oxvif::VideoRateControl2;
let rate = VideoRateControl2 {
    frame_rate_limit: 12.5,
    bitrate_limit: 2048,
};
assert_eq!(rate.frame_rate_limit, 12.5);
```

僅收件確認的 Media1 Mock 測試：

```rust
use oxvif::mock::{AckOnlyOperation, MockTransport};
let transport = MockTransport::new()
    .with_acknowledgment_only(AckOnlyOperation::MediaSynchronizationPoint);
```

詳細遷移範例：[frame rate](../media2-frame-rate_zh.md)、
[audio／metadata](../audio-metadata_zh.md)、
[profile assembly](../active/mock-fidelity-profile-assembly_zh.md)。
Metadata 仍為建模子集合，對實機 read-modify-write 無法保留未表示的 vendor／
event／filter 設定。

## 驗證與限制

正式版號前審查增加 in-process 與 HTTP 的整數 rate encoder replay 控制，
補充既有 fractional-rate 測試，驗證拒絕後錄製保留、Media2 成功提交後六種
相關讀取更新，以及兩種無關錄製保留。見[審查證據](../active/release-0.17-review_zh.md#v01-編碼器-replay-覆蓋)；
這不是新的產品修正，也不代表完整 replay 相容性驗收。

共用快照修復取代原先分離的 CLI／health 下載路徑。HTTP/1.1 首字母大寫標頭
處理已重現的韌體相容性問題，Digest 參數仍維持標準引號格式。Health 不再於
Digest 失敗後降級 Basic，並共用 16 MiB、同主機、禁止重新導向／proxy／HTTPS
降級及總期限政策。新增 `with_snapshot_options` builder 設定快照專用 CA 及期限。
Challenge 解析涵蓋 scheme／參數大小寫、引號清單、可支援選項與空 GET auth-int；
同一安全政策下最多進行一次 stale 重試。

回歸 fixture 會驗證實際 Digest 摘要，再回傳合成 JPEG；錯誤帳密與被改壞的摘要
都會遭拒。檔頭辨識不是解碼，PNG／BMP 仍為非 ONVIF 相容擴充。已發布 0.15
歷史中的 qop 解釋不是本批次 401 的已證實原因。修復後候選的實測結果及尚未完成
關卡記錄於[快照批次](../active/snapshot-auth-repair_zh.md)及
[審查資料](../active/release-0.17-approval_zh.md)。

正式版號前的審查另修正 snapshot Digest Authorization 的引號：`qop` 依
RFC 7616 第 3.4 節維持未加引號 token，不改寫成 WWW-Authenticate 使用的
quoted-list 語法。未放寬憑證、TLS、重新導向或認證降級策略；詳見
[維護指南](../cli-maintenance_zh.md#快照下載)。

本機候選基準：all-features 1,298、workspace default 1,190 通過，各五項 ignored；
兩組 Clippy、fmt、strict docs、Rust 1.88 及獨立 XML feature 控制通過。
選定外部 corpus 有 160 份 XML／80 次交換／46 個操作，含 21 次拒絕。
Source inventory 有 159 routes／161 Action 宣告／191 reader sites。
這些數字衡量不同事物，不是覆蓋百分比或 ONVIF 認證。

既有 synthetic Windows terminal／首次使用控制記於 CLI 計畫；不代表人類研究、
最終候選實機證據或 macOS／Linux 終端驗收。0.16.0 版號的 library dry-run
不等於最終 0.17 library／CLI 套件驗收。維護者已啟動
[`111c185` 的原生 CI](https://github.com/smiti1642/oxvif/actions/runs/34594415559)：
Windows、兩種 Linux 及 macOS ARM 測試 job 通過；macOS Intel 的四項 CLI 維運
測試失敗，Package/docs 因此略過。Runner 時序目前僅為工作假設，非已證實根因，
因為舊斷言未保留錯誤細節。後續修正將 30 秒功能測試預算與明確的 10／100 毫秒
deadline 控制分開，增加延遲 HTTP／SOAP 進度控制與失敗證據，保留 16 MiB 限制、
exit code 及不覆寫檢查。該測試預算修正未改產品行為；後續
[`3eccfd1` 的 run](https://github.com/smiti1642/oxvif/actions/runs/34597167495)
全部 27 個 job 通過，但只驗證該提交，不涵蓋之後的修正。Package/docs 驗證
library package，但 CLI 僅列出套件檔案，仍須散布 staging。之後的無效 UTF-8
拒絕修正及目前驗收結果，記錄於下方發布切點。

2026-09-12 的 [run 34672460802](https://github.com/smiti1642/oxvif/actions/runs/34672460802)
在 `fed6777fbc869a125082d9e2f43fb1a5e460f167` 全部 27 個 job 通過，涵蓋 Windows、
