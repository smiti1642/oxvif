## 目標與範圍

1. 在 manage 選單、獨立 Profile 選擇、Discovery 及可捲動結果中，提供一致的
   `gg`、`G`、數字指定移動及混合式相對行號。
2. 保留方向鍵、Home／End、整頁及半頁操作。文字、密碼及搜尋輸入與導航序列隔離。
3. 建立可獨立測試、行為確定的導航核心，供其他 Rust CLI 重用，不引入 ONVIF、
   設備清單、網路或終端後端。這是 Vim 風格導航子集，不是完整 Vim 模擬器。

不新增編輯運算子、巨集、暫存器、自訂按鍵、持久化 UI 偏好、新搜尋引擎或攝影機操作。
既有搜尋維持可用；為 manage 新增搜尋屬另一項功能。不更動 Agent schema、退出碼、
命令選擇器、憑證或攝影機寫入行為。

## 互動契約

`n` 表示正整數十進位前綴。清單操作以目前篩選後的排列為準，不使用設備 ID 或原始
探索紀錄編號作為導航位置。

| 輸入 | 結果 |
| --- | --- |
| `j`／`k`、下／上方向鍵 | 向下／向上移動一筆或一個顯示行。 |
| `nj`／`nk`、數字加下／上方向鍵 | 向下／向上移動 `n` 筆或顯示行。 |
| `gg`、Home | 到最前方。單按 `g` 等待下一鍵。 |
| `G`、End | 到最後方。 |
| `nG`、`ngg` | 到從 1 起算的第 `n` 筆；超出範圍時停在最後一筆。 |
| PgDown／PgUp | 移動一個完整可視頁；數字前綴乘上該移動量。 |
| Ctrl+D／Ctrl+U | 移動半個可視頁，向下取整且至少一筆／行；數字前綴乘上該移動量，不持續改變頁面大小。 |
| Discovery 中的 `h`／`l` | 保留既有向前／向後整頁別名；不擴充到文字輸入或其他畫面。 |
| 有數字或 `g` 前綴時按 Esc | 清除序列，不離開畫面。 |
| 無未完成序列時按 Esc | 維持該畫面原有返回／取消行為。 |
| Enter、`i`、`q`、`/`、篩選按鍵 | 無未完成導航序列時，維持既有畫面操作。 |
| Ctrl+C | 即使有未完成序列，仍維持立即取消／退出行為。 |

初版不接受數字加 `h`／`l`、Home／End 或應用操作。單獨 `0` 不開始計數，但可接在
既有數字後，例如 `10j`。數字上限為六位（`999999`）；後續數字拒絕接受並顯示簡短
提示，已接受的前綴維持可見且可取消。運算須先處理溢位再限制到有效範圍，即使輸入
極大數字，也不得逐筆迴圈計算移動。

在有界狀態區顯示待完成序列，例如 `12` 或 `12g`。不設定按鍵時限，允許緩慢輸入；
Esc 明確取消。遇到不支援的序列，例如 `3i` 或 `gq`，清除前綴、消耗該失敗按鍵並
顯示簡短提示，不可意外開啟詳情、選取項目或退出。有未完成前綴時按 Enter 亦同。
沒有前綴且核心不處理的單鍵，仍交由原畫面決定。

只有導航模式將按鍵送入解析器。終端轉接層忽略按鍵釋放事件及數字／`g` 前綴的按住
重複事件；移動鍵可持續重複。在搜尋、使用者名稱、密碼及路徑輸入時，`gg`、數字及
`j`／`k` 都是文字，Ctrl+U 保留清空功能。切換模式／畫面、變更篩選、取代或重排資料、
取消及調整終端大小時，清除未完成序列；從詳情返回不得還原舊數字前綴。

相容性注意：目前 Discovery 單按 `g` 即到第一筆，實作後改為 `gg`；Home 仍可立即
跳到最前方。應明確記錄此變更，不保留會造成序列歧義的單鍵 `g` 別名。

## 相對行號與可視範圍

- 採混合式行號欄：目前選取項目顯示從 1 起算的絕對序號，其餘可見項目顯示與
  選取項目的距離。例如游標下方七筆標示 `7`，可輸入 `7j` 到達。
- 保留 `>` 選取標記。導航序號不是設備 ID；既有設備 ID、原始探索紀錄編號及
  註冊資訊仍須可取得，且標示應與導航行號明確區別。
- 行號欄寬依完整篩選結果筆數計算，不依目前頁面決定。導航時資料欄置中及分隔符
  位置不變。先從內容寬度扣除行號欄，再進行 Unicode 安全的截斷或換行。
- 將選取位置與可視範圍起點分開維護。單筆／數字指定移動僅在需要顯示選取項目時
  捲動；整頁／半頁移動同時平移兩者並限制邊界。`gg`／`G` 顯示第一／最後一筆，
  絕對位置跳轉顯示目的項目。到達兩端不循環。
- 唯讀文字檢視器以第一個可見顯示行作為相對行號基準，不建立可編輯游標。
  數字以換行後的顯示行計算；`G` 顯示最後一頁，`nG` 在空間允許時將指定行放到最上方。
- 篩選後以符合項目重新建立導航序號並清除前綴。資料變更時，如有穩定身分識別，
  依該識別保留選取；否則將既有序號限制在有效範圍，絕不自動啟動項目操作。
- 空清單顯示明確空狀態，不出現虛構第 `1` 筆或可選列。低高度終端優先保留可見
  選取項目與返回／取消提示，先隱藏裝飾及相對行號細節。調整大小後重新計算行列
  預算並保留有效選取。文字重排可能改變行號，須清除前綴，但不要求保持精確文字錨點。

## 可重用架構

採三層責任界線；以下型別概念尚非公開 API。

| 層 | 責任 | 不得負責 |
| --- | --- | --- |
| 純核心：`crates/oxvif-cli/src/navigation.rs` | 後端無關按鍵模型、數字／`g` 狀態、解析結果、導航意圖、有界可視範圍計算及相對行號值 | crossterm 事件、終端 I/O、ONVIF、憑證、設備清單儲存或非同步工作 |
| 終端轉接層：`interactive.rs` | 轉換 crossterm 事件、分派輸入模式、繪製行號／狀態／提示、配合終端尺寸 | 各自複製的數字解析器或移動運算 |
| 應用層：`manage.rs` 與 Discovery 處理器 | 提供項目及穩定身分，保留選取／詳情／搜尋／加入／取消語意 | 解讀 Vim 序列或在導航狀態中儲存密碼 |

核心回傳明確結果：等待輸入、導航動作、已消耗的取消／無效序列，或未處理按鍵。
導航動作表達相對移動、最前／最後及絕對目的位置。呼叫端提供筆數與可視尺寸，核心
回傳限制於有效範圍的狀態，不讀取項目內容。清單選取與文字捲動政策需明確區分，
不得依賴 ONVIF 專屬判斷。

初期在既有 CLI binary 內編譯此模組，不改 workspace／套件相依圖，不發布新的
公開 API。新增以一般 `rustc --test` 編譯相同原始碼的小型無後端測試程式，證明
核心不依賴 oxvif 其餘部分；測試真正共享的原始碼，不複製另一份實作。現有套件檔案
包含規則須涵蓋新原始碼及測試。

未來抽取為獨立 crate 是另一里程碑：另定套件名稱、版本、MIT 授權標示、README 及
API 相容性政策。在宣稱通用採用前，應先由第二個 CLI 透過轉接層使用。不為
`oxvif-cli` 加入尚未發布且只有 path 的執行期相依；抽取前先確認命名及發布順序。

## 驗證

| 層面 | 必備證據 |
| --- | --- |
| 解析器 | `gg`、`G`、`12j`、`5k`、`42G`、`42gg`、多位數中的零、無效／過長前綴、連按兩次 Esc、Ctrl+C、大小寫／修飾鍵、重設事件及不支援的數字與動作組合 |
| 移動 | 空／單筆／大量清單、奇數／一行／零尺寸可視範圍、兩端邊界、大數飽和運算、絕對跳轉、整頁／半頁操作及資料變更 |
| 顯示 | 絕對／相對行號正確、跨頁行號與資料欄寬固定、Unicode、無控制字元洩漏、待完成提示、空狀態及選取項目可見性 |
| 模式隔離 | 搜尋清空、輸入 `123ggjk`、密碼遮蔽、貼上不執行導航、模式切換、詳情返回及取消行為不變 |
| 重用 | 以一般 Rust 工具編譯測試同一份核心，不依賴 Cargo／ONVIF／crossterm |
| 自動化 | 既有 JSON／JSONL、非互動及重新導向命令測試不變且通過，不混入行號、ANSI、按鍵提示或互動要求 |

刻意擾動數字處理、`gg` 完成條件或相對行號計算，確認對應斷言失敗，還原後才執行
完整驗證。不能只以編譯成功或僅檢查「有錯誤」的測試作為證據。

執行 workspace 格式檢查、預設／全功能 all-target Clippy（`-D warnings`）、
預設／全功能測試與 Rust 1.88 相容性檢查。若修改公開 rustdoc 介面或內部文件連結，
另執行對應的警告視為錯誤文件建置。

使用隔離設備清單，至少 40 筆合成設備，名稱包含長短、ASCII 及 Unicode；不使用
真實憑證或掃描實際網路。在 Windows 真實終端操作 `gg`、`G`、`7j`、`3k`、`21G`、
半頁／整頁、無效序列取消、詳情返回、輸入清空及視窗尺寸變更。流程需要資料時僅用
loopback mock。保留使用者正在執行的 CLI；Windows 鎖定執行檔時，另建或複製測試產物。

記錄選取位置／可視範圍的預期與實際結果，以及終端正常還原。宣稱三平台 UX 驗收前
必須完成 macOS／Linux 原生終端檢查；Windows 與純核心測試不足以證明。若實作階段
另要求獨立首次使用者 Critic，應在主 Agent 測試後進行，並區分 Agent 模擬體驗與
真人研究。
