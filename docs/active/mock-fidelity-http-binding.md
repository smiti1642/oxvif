## Contract

Original source at `afe3731`: MockServer::handle_soap → helpers::extract_action → Chain::respond_at.
HttpTransport accepts SOAP bodies on 200/400/500. Existing Content-Type extraction
splits semicolons and recognizes only lowercase action; every pipeline response
currently uses HTTP 200. Request::parse retains QName scope for response inspection.
No service payload, Action registry, public RequestCtx or in-process API changes.
The uncommitted candidate replaces extraction with `http_binding::action` and
maps returned XML through `http_binding::response_status`; the preceding paragraph
describes the historical starting point, not the candidate's behavior.

Reference: [W3C SOAP 1.2 Part 2, second edition](https://www.w3.org/TR/soap12-part2/),
§6.5.3 and §7.5.2. Reviewed conclusion: action is an optional nonempty absolute URI;
Sender maps to 400 and other standard envelope Fault codes to 500. Unsupported
encapsulation uses 415; malformed HTTP input uses 400 before SOAP processing.

Target mock policy: one Content-Type, at most 8192 bytes, application/soap+xml;
case-insensitive media type and parameter names, optional UTF-8 charset; parse
quoted strings/escapes, preserve action case, reject duplicate parameters and
malformed values. Unsupported media/charset/content coding returns 415; duplicate,
invalid or oversized header syntax returns 400. Absent Content-Encoding or a single
identity coding is accepted. Unknown well-formed parameters are ignored. Header
rejections have fixed plain-text bodies (no request echo) and precede auth/fault
consumption. Existing invalid UTF-8 SOAP-body refusal remains unchanged.

Missing action remains absent: HB1 does not invent a Body or WS-Addressing fallback;
the existing routing pipeline decides the result. SOAPAction is ignored as before.
Supplied action must have an ASCII URI scheme and nonempty ASCII URI remainder,
with valid percent escapes and no fragment, whitespace, controls or URI delimiters
requiring encoding. Full operation URI and Body agreement remain existing policy.

Inspect only a unique direct SOAP 1.2 Fault and its direct Code/Value using scoped
QNames. Map SOAP Sender to 400, other recognized envelope codes to 500. Legacy
nonstandard codes, raw malformed XML and non-Fault responses retain 200; raw body
bytes are never rewritten. SOAP response Content-Type remains for client compatibility.
This bounded policy is not full HTTP/SOAP/WS-Addressing conformance or endpoint mapping.

### Reproduced implementation defects

| ID | Source and affected surface | Reproduction and impact | Required change and acceptance |
| --- | --- | --- | --- |
| HB1-R01 | `src/mock/http_binding.rs::absolute_action`; all SOAP HTTP requests before the responder chain | `urn:bad[part]/GetDeviceInformation`, `http://[not-an-ip]/GetDeviceInformation` and `http://example.test:abc/GetDeviceInformation` pass the character whitelist. With a matching armed Receiver fault, each returns SOAP/500 and consumes that fault instead of the fixed HTTP/400 header refusal. | Validate RFC 3986 component structure, including bracketed hosts, port grammar and path/query characters. Preserve the original action string without URL normalization or network resolution. Each malformed case must return the exact fixed text/400, retain the armed fault and nonce, and leave device/hooks unchanged. Positive controls must include opaque URIs, IPv6 hosts, escaped characters and quoted semicolons. |
| HB1-R02 | `src/mock/http_binding.rs::response_status` using `Request::parse`; HTTP replay/raw response status | A replayed Sender envelope with a literal `<` in an attribute, an attribute named `1bad`, or a child named `1bad` returns 400. Response bytes remain unchanged, but the documented malformed-raw fallback is 200. The reused request parser does not establish XML well-formedness for these lexical cases. | Establish bounded lexical XML validity before mapping a scoped Fault code; preserve raw bytes and the documented 200 fallback. Share a reviewed validation boundary where practical without widening legacy in-process parsing or allocating an unnecessary second DOM. Test these malformed cases, valid equivalent Sender/Receiver responses, and explicit byte/depth/node-limit fallback behavior. |

Reference conclusions: [SOAP Part 2 §6.5.3](https://www.w3.org/TR/soap12-part2/)
requires an absolute, nonempty action URI; [RFC 3986 §3.2–3.4 and §4.3](https://www.rfc-editor.org/rfc/rfc3986.html#section-3.2)
define component grammar, not just an overall character whitelist. Square brackets
are limited to IP-literal hosts and ports contain digits. The existing mock's
additional nonempty-remainder rule must remain documented as local policy rather
than being inferred from the RFC's nonempty-URI requirement. SOAP Part 2 §7.5.2,
Table 20 supports the existing Sender/400 and other standard-code/500 mapping;
that table does not make malformed raw fixtures valid SOAP Faults.

Independent local HTTP probes reproduced both findings: three malformed action
cases consumed their armed fault; three malformed raw XML cases retained bytes
but changed status to 400. A valid raw Sender control returned 400. The two probe
tests pass by asserting the observed defects, not by proving correctness. Their
scratch source/log remain under ignored `target/hb1_review_probe.rs` and
`target/hb1-review-probe.log`; the temporary integration-test file was removed.
Convert these cases into normal regression assertions when implementing the fixes.

## Local implementation and acceptance, 2026-11-10

Disposition: R01 and R02 implemented; scoped local acceptance PASSED. HB1 remains
IN-PROGRESS for delivery and uncommitted at the user's explicit request.

- R01: `absolute_action` now separates hierarchy/query, authority, user information,
  host and port. RFC 3986 character classes apply per component; bracketed hosts
  accept IPv6 or IPvFuture grammar and ports accept only digits (including the
  RFC's empty port). The exact Action string is retained. No URL normalization,
  resolution, dependency update or public signature change is introduced.
- R02: `response_status` reuses the production lexical validator through a private
  crate re-export before constructing the scoped request tree. It adds no second
  DOM and does not change the legacy in-process parser. Invalid raw XML keeps 200
  and its exact response bytes. Inspection also falls back to 200 above 2 MiB,
  root-inclusive depth 64 or 16,384 elements; exact-limit controls still map the
  Sender code to 400. This is bounded inspection, not full Fault schema validation.
- Header tests cover the three reproduced bad URIs, malformed quoted escapes,
  duplicate Content-Encoding and actual HTTP 8192/8193-byte Content-Type values.
  Framework body buffering is explicit: a body above 2 MiB yields 413 before
  representation checks, including with unsupported media.
- The authenticated read control verifies rejected headers preserve the armed
  fault, nonce, state and hooks. The replay-backed SetHostname control additionally
  uses invalid representation headers with a valid write Action. It checks state,
  hooks and replay before rejection shape, then proves a valid write commits once
  and switches the recorded read to the live hostname.
- Raw replay controls assert exact bytes and status for valid Sender/Receiver and
  the three malformed XML cases. Unit controls add duplicate Code/Fault/Body,
  wrong-namespace decoys and inclusive byte/depth/node limits.
- Actual auth/service refusals retain full typed Fault fields. Session failure
  retains `DeviceFault` and unknown HTTP status in its report, as required by the
  String transport contract. The existing CLI test
  `ordinary_mock_auth_fault_preserves_human_and_agent_error_contracts` exercises
  human/JSON classification and exit 20 in the workspace gate; no copied CLI test
  is needed for this same boundary.
